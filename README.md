# FSM Desk — Платформа управления выездным обслуживанием

Платформа для диспетчеризации заявок, управления объектами, складского учёта и администрирования сервисной компании.

**Стек:** FastAPI · PostgreSQL · React · TypeScript · Redis · Docker

---

## Возможности

### 📋 Заявки (тикеты)
- FSM жизненного цикла: `ASSIGNED → ACCEPTED → ON_THE_WAY → ARRIVED → IN_PROGRESS → REVIEW → COMPLETED`
- Приоритеты: низкий / средний / высокий / критический
- Внутренние и клиентские заявки
- Назначение инженера, учёт просрочек, комментарии, вложения
- Три режима просмотра: таблица (drag-n-drop колонок), карточки, дерево
- Фильтрация по статусу, поиск, сохранённые представления

### 📦 Склад
- Складские документы: приход, перемещение, списание
- FSM документов: `DRAFT → APPROVAL → DELIVERY → ACCOUNTED`
- Номенклатура: материалы, продукты, услуги, работы
- Остатки по складам, раздельный учёт
- Контроль доступа по ролям (storekeeper, admin)

### 🏢 Объекты и клиенты
- Реестр объектов обслуживания с адресами, контактами, договорами
- Привязка ответственного инженера
- Управление клиентами (CRUD)

### 👥 Сотрудники
- Роли: администратор, инженер, диспетчер, кладовщик, заказчик
- Добавление и редактирование пользователей

### ⚙️ Администрирование
- Дашборд статистики системы
- Журнал действий (history.log)
- Управление пользователями, клиентами

## Архитектура

Модульный монолит с разделением на слои:

```
backend/
├── src/
│   ├── api/          # Контроллеры (FastAPI роутеры)
│   ├── core/         # FSM-движок, зависимости, исключения
│   ├── models/       # SQLAlchemy 2.0 модели (async)
│   ├── services/     # Бизнес-логика
│   └── ws/           # WebSocket менеджер
├── tests/            # Unit + acceptance тесты
└── history.log       # Аудит-лог действий

frontend/
├── src/
│   ├── api/          # Axios-клиент с 401-интерсептором
│   ├── components/   # Переиспользуемые компоненты (TicketGrid и др.)
│   ├── pages/        # Страницы приложения
│   ├── hooks/        # useDebounce, useWebSocket
│   ├── store/        # Zustand сторы
│   └── locale.ts     # Русская локализация
```

**Ключевые принципы:**
- Смена статуса только через FSM с гардами
- Изменения склада только через учётные документы
- Бизнес-логика не живёт в контроллерах
- Все UI-надписи — на русском языке

## Запуск

### Docker (рекомендуется)

```bash
cd docker
docker-compose up -d
```

### Ручной запуск

**Бэкенд:**
```bash
cd backend
pip install -r requirements.txt
cp .env.example .env    # поправить DATABASE_URL
alembic upgrade head
python3 -m uvicorn src.main:app --host 0.0.0.0 --port 8002
```

**Фронтенд:**
```bash
cd frontend
npm install
npm run build            # статика в frontend/dist/
```

Бэкенд раздаёт API и статику фронтенда на одном порту. После сборки фронт доступен по адресу сервера.
